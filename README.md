LiveLog 首页使用卡片翻阅轮播样式，演出详情展示海报、座位、票价和现场相册。未来日期的演出标为“待赴现场”，不计入已看场次、城市、歌手和年份统计。

记忆拼贴墙中有多张现场照片的卡片，每 5 秒以 1.2 秒的淡入淡出动画轮播，右上角显示当前图片序号；单张照片或仅有海报时保持静态。可使用筛选栏中的“暂停照片轮播”按钮控制播放，卡片移出屏幕、打开弹窗或页面进入后台时也会暂停，鼠标停留或卡片获得焦点不影响轮播。系统启用减少动态效果时不自动轮播。Safari 17+ 可直接打开本地 HTML 展示配对实况图的原始 HEIC；实况图在拼贴墙仅展示静态照片，不加载视频。

在项目目录启动本地预览：

```sh
python3 -m http.server 8765 --bind 127.0.0.1
```

打开 [本地首页](http://127.0.0.1:8765)。部署时将整个项目作为静态网站发布，保留 `public` 目录路径。

Safari 17 或更新版本也可直接打开项目中的 `index.html`，查看本地实况照片并点击实况图标播放。请保留页面、脚本与 `public` 的目录结构。其他浏览器建议使用上面的 HTTP 预览方式。

部署到 GitHub Pages 时，发布源根目录必须包含空文件 `.nojekyll`（本项目已提供）。项目直接发布静态文件，无需 Jekyll 构建；该标记用于避免 Jekyll 忽略 `_web/` 等下划线开头的素材目录，否则转换后的海报和现场照片会返回 404。更新时一并提交该文件与 `public/concert/**/_web/` 中的素材，等待 Pages 部署完成后刷新页面。若改为从 `docs/` 或其他目录发布，也需要将该标记放在对应发布源根目录。

演出基本信息读取上方表格，补充信息在 `public/concert/metadata.json`。静态海报和照片的存放方式不变；每张实况图可使用一个子文件夹，放入同名 HEIC 和 MOV，例如：

```text
public/concert/2025-07-13/
  poster.JPG
  live/
    IMG_0136/
      IMG_0136.HEIC
      IMG_0136.MOV
```

`live/` 下可放置多个实况图子文件夹。扫描会递归读取，按“同一文件夹、相同文件主名”配对，主名和扩展名匹配不区分大小写；同名文件分散在不同文件夹时不会误配。旧的 `live/IMG_9573.HEIC + live/IMG_9573.mov` 平铺结构仍可使用。隐藏文件和 `_web/` 中已有生成文件不会被当作新增素材。

更新表格或添加素材后重新生成清单：

```sh
python3 -m pip install -r scripts/requirements.txt
python3 scripts/sync-concerts.py
```

`public/concert-data.js` 自动记录实况图的原始 HEIC/MOV 地址，不生成实况图的 JPEG/MP4，不需要 ffmpeg 或 Swift。海报、没有配套视频的单张 HEIC 继续按原方式转为 `_web/` 内的 JPEG，普通图片路径不变；未配对的视频直接作为现场视频展示。旧的实况转换文件不再用于实况展示，确认清单未引用后可以删除；仍被引用的静态转换图片需要保留。

播放器使用本地保存的 [thun888/LivePhoto 1.2.0](https://github.com/thun888/LivePhoto)，位于 `public/vendor/live-photo/1.2.0/`。HEIC/HEIF 优先由浏览器原生显示；HTTP 访问下，原生显示失败时通过组件解码为内存图片。Safari 本地文件访问直接读取原片，避免 `fetch(file://)` 限制。MOV 交给浏览器直接播放，素材不会上传第三方服务。`live-photo.js` 负责项目接入、原生图片加载、生命周期和键盘操作。版本、许可证与可复现的本地保存步骤见该目录的 `README.md`。

点击相册中带 `◉ LIVE` 标记的照片打开查看器；悬停或按住照片左上角的实况图标播放，离开或松开停止，也可点击图标播放。默认开启声音，可通过旁边的声音图标静音。拼贴墙与相册缩略图只加载照片，不预加载或播放 MOV；进入查看器后按需加载视频。关闭、切换照片或切到后台会停止播放并释放组件资源。

原始 MOV 的播放能力取决于浏览器和系统的视频解码支持，组件不执行视频转码。无法播放时会保留照片并显示提示。Safari 如果阻止悬停时有声播放，点击实况图标重试即可；无需修改浏览器安全设置。不支持原生 HEIC 的浏览器直接打开 `file://` 文件时，会提示改用 Safari 17 或更新版本，或使用 HTTP 预览。

发布到 GitHub Pages 时，一并提交更新后的清单、页面与适配器、原始 HEIC/MOV，以及整个 `public/vendor/live-photo/1.2.0/`（含 `931.bundle.js` 解码分块与许可证），并保留 `.nojekyll`。静态图片所需 `_web/` 文件仍需部署。
