## 唱片架

唱片架从本机读取你的黑胶和 CD 收藏。添加第一张唱片后，首屏会展示它的封面。首屏、唱片卡片及详情页支持静音播放动态封面。

双击 `albums.html` 即可浏览唱片架，也可从 `index.html` 进入。已归档的静态封面和动态 MP4 从项目目录直接读取，离线可用。封面搜索和外部图片链接需要联网。

通过 HTTP 或 HTTPS 浏览时，归档的动态封面沿用本地 HLS 清单和分片。Chrome 使用本地固定版本 HLS.js 1.7.3，Safari 优先原生 HLS。播放器代码与许可证位于 `public/vendor/hls/1.7.3/`。动态封面加载失败时保留静态封面，并提供重试入口。

动态封面仅在可见区域播放；离屏、进入后台、打开其他弹窗时停止并释放流，关闭详情或筛选移除卡片时清理播放器和观察器。系统启用减少动态效果时默认显示静态封面，仍可手动播放。

添加唱片时，输入专辑名称后点击「搜索封面」，也可加上音乐人缩小范围。封面区最多展示三个候选，动态封面排在前面，可见时静音预览。相同类型的搜索结果沿用 iTunes 的顺序。点选会带入封面，音乐人留空时也会带入该结果的音乐人。也可以手动填写图片地址，或留空显示占位图。可选填实体版本、购入价格和购买渠道，这些信息可在唱片详情查看。

使用桌面版 Chrome 或 Edge 直接打开 `albums.html`。首次保存时按浏览器提示授权当前项目的 `public` 文件夹，权限有效期间以后保存会复用该目录。唱片资料写入 `public/albums/专辑名/album.json`，页面同时更新 `public/album-data.js`。即使没有封面也会创建目录，同名专辑目录自动加序号。编辑已归档的专辑时沿用其现有目录。

旧版保存在浏览器的唱片，可在原浏览器打开本地唱片架，在详情选择「编辑唱片」并保存。页面会沿用原记录编号归档。

专辑有本地封面时，封面文件保存在对应的归档目录。网页保存的在线封面保留链接，缺少封面的唱片显示占位图。用编辑器直接修改归档文件后，可运行 `python3 scripts/sync-album-data.py`，更新清单，并从兼容的 HLS 分片生成 `motion.mp4`。生成的清单和 MP4 需与归档素材一同保留。

#### Apple 封面获取流程

1. 用 [iTunes Search API](https://performance-partners.apple.com/search-api) 搜索专辑。发送 `GET https://itunes.apple.com/search`，把专辑名称和可选的音乐人放入 `term`，并传入 `media=music&entity=album&country=tw&limit=24`。滤掉标为单曲的发行，再从其余结果识别动态封面，最后最多展示三个候选。
2. 静态封面从对应结果的 `artworkUrl100` 取得。候选预览和保存优先使用同一图片的 600×600 版本，加载失败时回退到接口返回的原地址。
3. 要查动态封面，对该结果的 `collectionViewUrl` 发起 HTTPS GET，解析返回的 HTML。在 `<script id="serialized-server-data">` 的 JSON 中匹配当前专辑头部，再读 `videoArtwork.dictionary.motionDetailSquare.video`。若存在，该值就是方形封面的 HLS 播放列表地址。该字段属于 Apple Music 的网页数据，结构和媒体地址可能变化。
4. 唱片架搜索使用 iTunes 返回的静态封面及项目已收录的动态封面地址，有动态封面的候选排在前面。

可用脚本从 Apple Music 专辑页更新本地清单。传入一个或多个完整专辑链接，脚本通过 HTTPS 读取页面并按专辑 ID 合并结果。浏览器双击打开时也会读取同一份清单。

```sh
python3 scripts/sync-album-motion.py 'https://music.apple.com/cn/album/sos/1658650093'
```

播放器生命周期检查：`node --test scripts/test-album-motion.cjs`。

LiveLog 首页采用支持明暗主题的沉浸式舞台与彩色海报悬浮空间。首屏直接展示歌手、演出名称、日期和场馆；点击两侧海报切换演出，点击当前海报打开详情；支持方向键、触屏滑动和手动暂停。首屏海报区、顶部导航、下方档案和详情统一跟随明暗主题，海报与现场图片保留原色。演出详情展示海报、座位、票价和现场相册。未来日期的演出标为“待赴现场”，不计入已看场次、城市、歌手和年份统计。

悬浮海报通过本地 `hero-space.js` 的 CSS 透视位置与事件驱动视差实现，不引入框架或图形库。鼠标视差仅作用于海报区域；暂停、离屏、后台或弹窗打开时停止，减少动态效果时关闭自动轮播和装饰动画。键盘焦点停留在轮播中时也暂停自动切换。

记忆拼贴墙中有多张现场照片的卡片，每 5 秒以 1.2 秒的淡入淡出动画轮播，右上角显示当前图片序号；单张照片或仅有海报时保持静态。可使用筛选栏中的“暂停照片轮播”按钮控制播放，卡片移出屏幕、打开弹窗或页面进入后台时也会暂停，鼠标停留或卡片获得焦点不影响轮播。系统启用减少动态效果时不自动轮播。Safari 17+ 可直接打开本地 HTML 展示配对实况图的原始 HEIC；实况图在拼贴墙仅展示静态照片，不加载视频。

双击项目中的 `index.html` 打开首页，保留页面、脚本与 `public` 的目录结构。使用 Safari 17 或更新版本可查看本地实况照片，点击实况图标播放。

部署到 GitHub Pages 时，发布源根目录必须包含空文件 `.nojekyll`（本项目已提供）。项目直接发布静态文件，无需 Jekyll 构建；该标记用于避免 Jekyll 忽略 `_web/` 等下划线开头的素材目录，否则转换后的海报和现场照片会返回 404。更新时一并提交该文件与 `public/concert/**/_web/` 中的素材，等待 Pages 部署完成后刷新页面。若改为从 `docs/` 或其他目录发布，也需要将该标记放在对应发布源根目录。

演出基本信息读取上方表格，补充信息在 `public/concert/metadata.json`。静态海报和照片的存放方式不变；每张实况图可使用一个子文件夹，放入同名 HEIC 和 MOV，例如：

```text
public/concert/2025-07-13/
  poster.JPG
  live/
    IMG_0136/
      IMG_0136.HEIC
      IMG_0136.MOV
```

`live/` 下可放置多个实况图子文件夹。扫描会递归读取，按“同一文件夹、相同文件主名”配对，主名和扩展名匹配不区分大小写；同名文件分散在不同文件夹时不会误配。旧的 `live/IMG_9573.HEIC + live/IMG_9573.mov` 平铺结构仍可使用。隐藏文件和 `_web/` 中已有生成文件不会被当作新增素材。

更新表格或添加素材后重新生成清单：

```sh
python3 -m pip install -r scripts/requirements.txt
python3 scripts/sync-concerts.py
```

`public/concert-data.js` 自动记录实况图的原始 HEIC/MOV 地址，不生成实况图的 JPEG/MP4，不需要 ffmpeg 或 Swift。海报、没有配套视频的单张 HEIC 继续按原方式转为 `_web/` 内的 JPEG，普通图片路径不变；未配对的视频直接作为现场视频展示。旧的实况转换文件不再用于实况展示，确认清单未引用后可以删除；仍被引用的静态转换图片需要保留。

播放器使用本地保存的 [thun888/LivePhoto 1.2.0](https://github.com/thun888/LivePhoto)，位于 `public/vendor/live-photo/1.2.0/`。HEIC/HEIF 优先由浏览器原生显示；HTTP 访问下，原生显示失败时通过组件解码为内存图片。Safari 本地文件访问直接读取原片，避免 `fetch(file://)` 限制。MOV 交给浏览器直接播放，素材不会上传第三方服务。`live-photo.js` 负责项目接入、原生图片加载、生命周期和键盘操作。版本、许可证与可复现的本地保存步骤见该目录的 `README.md`。

点击相册中带 `◉ LIVE` 标记的照片打开查看器；悬停或按住照片左上角的实况图标播放，离开或松开停止，也可点击图标播放。默认开启声音，可通过旁边的声音图标静音。拼贴墙与相册缩略图只加载照片，不预加载或播放 MOV；进入查看器后按需加载视频。关闭、切换照片或切到后台会停止播放并释放组件资源。

原始 MOV 的播放能力取决于浏览器和系统的视频解码支持，组件不执行视频转码。无法播放时会保留照片并显示提示。Safari 如果阻止悬停时有声播放，点击实况图标重试即可；无需修改浏览器安全设置。不支持原生 HEIC 的浏览器直接打开 `file://` 文件时，会提示改用 Safari 17 或更新版本。

发布到 GitHub Pages 时，一并提交更新后的清单、页面与适配器、原始 HEIC/MOV，以及整个 `public/vendor/live-photo/1.2.0/`（含 `931.bundle.js` 解码分块与许可证），并保留 `.nojekyll`。静态图片所需 `_web/` 文件仍需部署。

本地档案与浏览器新增记录分开保存。重新生成素材清单后，已有浏览器也会读取最新本地档案；新增和隐藏记录保存在当前浏览器，可通过页尾导出 JSON 备份。

唱片架页面沿用首页的黑白明暗主题、无衬线字体和简洁导航；彩色封面保留原色，专辑详情与添加表单使用同一套视觉样式。
